# Architecture and lifetime

`src/ipheth.c` has no memory allocation, OS calls, USB transfers, unaligned integer reads, or dependencies beyond the C library. Callers supply complete USB RX transfers and synchronous frame consumers. NCM tables are completely validated before any callback is invoked, including termination, arithmetic, frame sizes and overlap. RX views cannot be retained after callback return.

The class parses the selected configuration, validates Apple VID and ff/fd/01, then chooses the lowest alternate with one bulk IN and one bulk OUT. No PID, USB configuration, interface number or endpoint address is fixed. With the current CherryUSB external class API, the class table matches the exact interface triplet and `connect` rejects non-Apple VID, because that API has only a combined VID/PID match table.

Each device owns its URBs, endpoint descriptors, DMA buffers, control setup, semaphores and TX mutex. EP0 setup does not reuse `hport->setup`; the stack's control-transfer lock serializes EP0 with other classes. No data transfer takes that shared EP0 mutex. USBMUX retains its own interface, private data and URBs.

A device worker submits asynchronous RX and receives completion through a semaphore; callbacks only publish results, never resubmit or touch the stack. The worker copies frames through the network adapter. Default activation follows Linux IPHETH: a first successful Bulk IN permits Carrier polling; empty/four-byte 00 01 xx xx control transfers establish `rx_ready` without delivering Ethernet frames. An optional `usbh_ipheth_host_ready(hport, true)` notification from an external, independently activated host session permits actual Carrier queries after a successful RX submission even without a first completion. A positive Carrier reply remains mandatory for link-up/TX; before observed RX readiness, TX also requires `host_ready` and `rx_armed`. Revocation immediately blocks this pre-RX TX path and the control worker lowers the link; an in-flight Carrier result rechecks activation. The hint is not authentication performed by this driver. Detach/reconnect resets it. A separate control worker polls Carrier once a second using a wrapping monotonic clock and a private EP0 mutex shared with halt recovery. Three failed transactions lower an established link; a successful down result is immediate. Normal RX never waits for the TX mutex; only actual TX STALL recovery takes it. USB faults retry with backoff. TX is synchronous with a 1 s timeout. See [porting](porting.md) for activation lifetime requirements.

On detach: mark stopping; wait for both RX and control worker acknowledgments; cancel outstanding RX; report link down; drain network TX users; clear only this interface's private pointer; delete synchronization objects and recycle the slot. Each worker acknowledgment is its last access to device storage. Failure to create either worker unwinds the network adapter and all five OSAL objects. A failed HCD cancellation quarantines the device slot and its objects instead of reusing possibly live DMA or callback memory. That deliberately costs a slot until reboot.

The RT-Thread adapter keeps its small `eth_device` objects and mutexes registered while unplugged. Queued tcpip packets can thus never refer to freed netif memory. Detached devices reject TX; reconnect reuses the device, updates its MAC in the lwIP thread and restarts IPv6 Link-Local DAD. No RX pbuf points into USB storage. A port must serialize all public send/stats users against its detach callback. Callbacks must not recursively disconnect the device or send from RX callbacks.

The current RT-Thread adapter expects its TCP/IP thread to have started before USB enumeration (the usual RT-Thread component initialization order). It does not force default-route changes. Socket users select the network interface or source address they intend to use.

Link notifications in the RT-Thread direct-RX adapter use synchronous netifapi link-up/down calls, including detach. They do not use the shared Ethernet RX mailbox, whose nonblocking post can fail under physical Ethernet load and lose the only carrier transition. No TX mutex is held across this core-serialized operation. This preserves IPv6 DAD and actual carrier readiness; it does not force the interface up.

Normal RX rearm does not acquire the synchronous TX mutex. Only a reported TX STALL enters the mutex-protected recovery path, rechecks halt/stop state and clears the endpoint/toggle using private EP0 storage. The pending-halt flag is published through OSAL critical sections. An actual-worker regression holds TX behind a test gate and requires a new RX submission before releasing that gate in both NCM and legacy modes. This removes one RX/TX lock dependency; a network adapter must also avoid synchronous protocol/output work in the RX callback if it needs receive progress while ACK transmission waits.
